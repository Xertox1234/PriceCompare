# Test Helpers - Quick Reference Guide

**Last Updated:** 2025-12-05

This directory contains shared test utilities to eliminate duplication and ensure consistent testing patterns.

## 📦 Available Utilities

### 1. Mock Infrastructure (Auto-Apply)

Import these at the **top** of your test file (before other imports):

```typescript
// Auto-mocks Redis client globally
import './helpers/mock-redis';

// Auto-mocks logger globally
import './helpers/mock-logger';
```

**What It Does:**

- Mocks `redisClient`, `getRedisClient()`, `isRedisConnected()`, etc.
- Mocks `log()`, `logger` from `utils/logger`
- Applied automatically via Vitest `vi.mock()`
- Zero setup code needed in your test

## 🚀 Quick Start Examples

### Example 1: Basic Test with Redis Mock

```typescript
// ✅ CORRECT

import './helpers/mock-logger'; // Auto-applies logger mock
import { createTestProduct, cleanupTestData } from './helpers/test-fixtures';
import { db } from '../db';

describe('ProductService', () => {
  afterEach(async () => {
    await cleanupTestData(db, ['products', 'retailers']);

    const productData = createTestProduct({ name: 'iPhone 15' });
    const [product] = await db.insert(products).values(productData).returning();

    expect(product.name).toBe('iPhone 15');
    expect(product.id).toBeDefined(); // Auto-generated by database
  });
});
```

## 🎯 Common Patterns

### Pattern 1: Mock Storage Layer

```typescript
import type { IStorage } from '../storage';

describe('Service Tests', () => {
  let mockStorage: IStorage;

  beforeEach(() => {
    mockStorage = {
      getProductById: vi.fn().mockResolvedValue(null),
      createProduct: vi.fn().mockResolvedValue({ id: 1 }),
      // Mock ALL methods the service uses
    } as unknown as IStorage;
  });

  it('should use storage', async () => {
    await service.doSomething(mockStorage);
    expect(mockStorage.getProductById).toHaveBeenCalledWith(1);
  });
});
```

---

### Pattern 2: Testing with Real Database

```typescript
import './helpers/mock-redis';
import './helpers/mock-logger';
import { createTestProduct, cleanupTestData } from './helpers/test-fixtures';
import { db } from '../db';

describe('Database Integration Tests', () => {
  afterEach(async () => {
    await cleanupTestData(db, ['products', 'retailers']);
  });

  it('should persist to database', async () => {
    const productData = createTestProduct();
    const [saved] = await db.insert(products).values(productData).returning();

    // Query to verify persistence
    const found = await db.query.products.findFirst({
      where: eq(products.id, saved.id),
    });

    expect(found).toBeDefined();
    expect(found?.name).toBe(productData.name);
  });
});
```

## ⚠️ Common Mistakes

### ❌ Mistake 1: Hardcoding IDs

```typescript
// ❌ BAD - ID will conflict with auto-generated database ID
const testProduct = {
  id: 1, // Don't do this!
  name: 'Test',
};
```

```typescript
// ✅ GOOD - Let database auto-generate ID
const productData = createTestProduct({ name: 'Test' });
const [saved] = await db.insert(products).values(productData).returning();
// saved.id is auto-generated
```

---

### ❌ Mistake 2: String Dates (Not Timezone-Safe)

```typescript
// ❌ BAD - Not timezone-safe
const testDate = '2025-12-05T00:00:00Z';
```

```typescript
// ✅ GOOD - Timezone-safe
const testDate = createTestDate(0); // Noon local time
```

---

### ❌ Mistake 3: Manual Mock Setup

```typescript
// ❌ BAD - Duplicates mock setup
vi.mock('../config/redis', () => ({
  redisClient: {
    get: vi.fn(),
    // ... 40 more lines
  },
}));
```

```typescript
// ✅ GOOD - Use shared mock
import './helpers/mock-redis';
```

---

### ❌ Mistake 4: Incomplete Storage Mock

```typescript
// ❌ BAD - Only mocks 2 methods, service calls 5
const mockStorage = {
  getProductById: vi.fn(),
  createProduct: vi.fn(),
} as unknown as IStorage;
```

```typescript
// ✅ GOOD - Mock ALL methods service uses
const mockStorage = {
  getProductById: vi.fn().mockResolvedValue(null),
  createProduct: vi.fn().mockResolvedValue({ id: 1 }),
  updateProduct: vi.fn().mockResolvedValue({ id: 1 }),
  deleteProduct: vi.fn().mockResolvedValue(undefined),
  getProductsByCategory: vi.fn().mockResolvedValue([]),
} as unknown as IStorage;
```

## 🔍 Debugging Tips

### Tip 1: Check Mock Was Applied

```typescript
import './helpers/mock-redis';

describe('Debug Mock', () => {
  it('should have mocked Redis', () => {
    // This will fail if mock wasn't applied
    expect(vi.isMockFunction(getRedisClient)).toBe(true);
  });
});
```

---

### Tip 2: Clear Mocks Between Tests

```typescript
describe('Tests', () => {
  beforeEach(() => {
    vi.clearAllMocks(); // Clear all mock call history
  });

  it('should start with clean mocks', () => {
    expect(mockStorage.getProductById).not.toHaveBeenCalled();
  });
});
```

## 🆘 Need Help?

**Common Questions:**

1. **"My tests fail with 'X is not a function'"**
   - Missing mock method. Add it to your storage/service mock.

2. **"Dates are timezone-dependent"**
   - Use `createTestDate()` instead of `new Date()` or string dates.

3. **"ID conflicts in tests"**
   - Don't hardcode IDs. Use `createTestProduct()` which omits ID field.

4. **"How do I mock a new service?"**
   - Create mock object with all methods the service exposes.
   - Use `as unknown as IServiceType` for type casting.
