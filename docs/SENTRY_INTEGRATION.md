# Sentry Error Monitoring Integration

Complete guide to Sentry error monitoring in the PriceCompare application.

## Overview

Sentry is integrated on both **backend** (Node.js/Express) and **frontend** (React) to provide comprehensive error tracking, performance monitoring, and session replay capabilities.

## Configuration

### Environment Variables

Add to `.env` file (see `.env.example` for reference):

```bash
# Backend Sentry DSN (from Sentry.io backend project)
SENTRY_DSN=https://your-backend-dsn@sentry.io/project-id

# Frontend Sentry DSN (from Sentry.io frontend project)
# Can be the same as backend or a separate project
VITE_SENTRY_DSN=https://your-frontend-dsn@sentry.io/project-id

# Optional: Set release version for tracking
SENTRY_RELEASE=1.0.0
VITE_SENTRY_RELEASE=1.0.0
```

### Backend Configuration

**File**: `/server/config/sentry.ts`

Features:
- ✅ Error tracking with filtering (operational errors excluded)
- ✅ Performance monitoring (10% sample rate in production)
- ✅ User context tracking
- ✅ Request/response breadcrumbs
- ✅ Graceful degradation (warnings if DSN not configured)

**Initialization** (in `server/index.ts`):
```typescript
import { initializeSentry } from './config/sentry';

// MUST be first - before any other imports
initializeSentry();
```

**Middleware Order** (in `server/index.ts`):
```typescript
// 1. Sentry request handler (FIRST!)
app.use(sentryRequestHandler);

// 2. Sentry tracing handler
app.use(sentryTracingHandler);

// ... other middleware ...

// N-1. Sentry error handler (BEFORE custom error handler)
app.use(sentryErrorHandler);

// N. Custom error handler (LAST!)
app.use(errorHandler);
```

### Frontend Configuration

**File**: `/client/src/main.tsx`

Features:
- ✅ React error boundaries integration
- ✅ Browser tracing for performance
- ✅ Session replay (10% of sessions, 100% of error sessions)
- ✅ Network error filtering (404s, CORS, etc. excluded)
- ✅ Validation error filtering (handled by UI)

**Initialization**:
```typescript
import * as Sentry from "@sentry/react";

// Initialize BEFORE React render
if (import.meta.env.VITE_SENTRY_DSN) {
  Sentry.init({
    dsn: import.meta.env.VITE_SENTRY_DSN,
    environment: import.meta.env.MODE,
    // ... config ...
  });
}
```

## Error Filtering

Both backend and frontend filter **operational errors** (expected errors) to reduce noise:

### Backend Filters
- ❌ CSRF token mismatches (expected attacks)
- ❌ Rate limit errors (expected abuse)
- ❌ Validation errors (user input errors)
- ❌ 404 Not Found errors
- ✅ Database errors
- ✅ Unhandled exceptions
- ✅ Service crashes

### Frontend Filters
- ❌ Network errors (CORS, timeouts, DNS)
- ❌ 404 Not Found
- ❌ Validation errors (Zod/form validation)
- ❌ React Query cache misses
- ✅ JavaScript errors
- ✅ React component crashes
- ✅ Unhandled promise rejections

## Source Maps

**Required for readable stack traces in production.**

### Frontend Source Maps

**Enabled** in `vite.config.ts`:
```typescript
export default defineConfig({
  build: {
    sourcemap: true, // REQUIRED for Sentry
  }
});
```

Source maps are automatically generated during production builds and included in the `dist/public` directory.

**Optional**: Upload source maps to Sentry using `@sentry/vite-plugin` (not currently configured).

### Backend Source Maps

Generated by `esbuild` during production build:
```bash
npm run build
# Generates dist/index.js with inline source maps
```

## Session Replay

**Frontend only** - Records user sessions for debugging.

**Features**:
- Screen recording of user interactions
- Console logs captured
- Network requests logged
- DOM mutations tracked

**Privacy**:
- Text visible (not masked) - adjust in `replayIntegration()` if needed
- Media visible (not blocked)
- No sensitive fields recorded (passwords auto-masked)

**Sample Rate**:
- 10% of normal sessions
- 100% of sessions with errors

## Testing the Integration

  throw new Error("Frontend Sentry Test - " + new Date().toISOString());

**Expected Result**:

## Graceful Shutdown

Backend Sentry is properly closed on shutdown:

```typescript
// In server/index.ts
process.on('SIGTERM', async () => {
  await closeSentry(2000); // Flush pending events
  process.exit(0);
});
```

**Ensures**:
- Pending errors sent before shutdown
- No data loss during deployment
- Clean connection closure

## Security Considerations

### Sensitive Data Protection

**Backend** (`server/config/sentry.ts`):
- Password fields automatically redacted
- Authorization headers filtered
- User PII excluded from breadcrumbs

**Frontend** (`client/src/main.tsx`):
- Password inputs auto-masked in session replay
- Credit card fields auto-masked
- PII fields excluded from error context

### beforeSend Hook

Both backend and frontend implement `beforeSend()` to:
1. Filter operational errors
2. Scrub sensitive data
3. Add additional context
4. Rate limit error reporting

Example:
```typescript
beforeSend(event, hint) {
  // Don't send validation errors
  if (hint.originalException?.name === 'ValidationError') {
    return null;
  }

  // Scrub sensitive fields
  if (event.request?.data) {
    delete event.request.data.password;
    delete event.request.data.creditCard;
  }

  return event;
}
```

## Troubleshooting

### Sentry Not Reporting Errors

**Check**:
1. Environment variables set (`SENTRY_DSN`, `VITE_SENTRY_DSN`)
2. DSN is valid (from Sentry.io project settings)
3. Error is not filtered by `beforeSend()` hook
4. Network connectivity to Sentry.io
5. Check browser/server console for Sentry initialization logs

### Source Maps Not Working

**Frontend**:
1. Verify `sourcemap: true` in `vite.config.ts`
2. Check `dist/public/assets/*.js.map` files exist
3. Upload source maps to Sentry (optional, using Vite plugin)

**Backend**:
1. Verify esbuild generates source maps
2. Check `dist/index.js.map` exists

### High Event Volume

**Reduce sample rates**:
```typescript
// Production settings
tracesSampleRate: 0.05, // 5% instead of 10%
replaysSessionSampleRate: 0.05, // 5% instead of 10%
```

**Increase filtering**:
```typescript
beforeSend(event, hint) {
  // Add more filters
  if (event.level === 'info' || event.level === 'warning') {
    return null; // Only send errors
  }
  return event;
}
```
